# INC-07 design notes (runs, metrics, observability; scheduler OFF)
Branch `stage-15-inc07-runs-metrics`. Labels: Verified Fact / Inference / Assumption / Unknown. Test data synthetic, unvalidated (the 125 shipped cases are the only non-synthetic-looking input, read through the hash-gated snapshot and still labelled). No AI/model call, no network egress, `zone_h.holders` empty in the shipped configuration.

## Decisions
- D-01 (Verified Fact) M005 lives in `hub/runs/migrations/` and is applied by `hub.runs.schema` with its own table `runs_schema_migrations` (INC-04/05/06 precedent), after a backup labelled `pre-runs-M005-`, sha256 drift checks; it needs M001..M004. It creates the full `run_event` table (closes the DDL part of RTD-53), `run_lock`, `metric_definition`, `metric_value`, `obs_metric`; every table is insert-only except `run_lock` (single-flight lock rows).
- D-02 (Verified Fact, OD-19) THE SCHEDULER IS OFF. There is no scheduler, timer, thread, sleep loop, cron or systemd file anywhere (S09 scans for them). A run is an explicit invocation (`RunService.run`, `python -m hub.runs run`). `trigger = scheduled` is a label supplied by the caller (an external scheduler, or a test at a controlled test-clock time); the service refuses it unless the schedule flag is on.
- D-03 (Verified Fact) The schedule flag is the latest `SCHEDULE_CHANGED` row of `policy_events`, written only by `ScheduleService.set_enabled` through the shared Zone H gate as ZH-09. Configuration cannot switch it on (`schedule.enabled: true` is E-CFG-INVALID). With the shipped empty holder list nobody can switch it on (E-GATE-NO-HOLDERS); a service actor is E-GATE-NOT-AUTHORISED. Scheduler vs HAR-10 stays an open human decision (RTD-59).
- D-04 (Verified Fact) A run record is a set of append-only `run_event` rows (RUN_STARTED, RUN_CHECKPOINT, RUN_FINISHED, RUN_FAILED, RUN_ABANDONED, RUN_REFUSED) folded on read; `RunService.to_schema` renders exactly run-record.schema.json (checked by a mini validator in the tests). Every start, refusal, failure and abandonment has a record and one audit record.
- D-05 (Verified Fact) Single flight per job via `run_lock` with a heartbeat (default stale after 900 s, A-12-F06-1). A fresh lock gives E-RUN-ALREADY-RUNNING and a refused record; a stale lock is reaped by the next start or `reap` (writes RUN_ABANDONED, actor `hub`, kind system). A killed run is shown as abandoned in reports before it is closed in the store.
- D-06 (Verified Fact) No hidden cap: batching jobs need an explicit `--batch-size` or `runs.batch_size` (no default; otherwise E-CFG-INVALID before anything starts). `limit_reached` and `backlog_remaining` are exact. `--until-empty` loops inside one run, one checkpoint per batch.
- D-07 (Verified Fact) The checkpoint is the per-source order key (`[source_ts, key, dup]`) of the last processed item; resume uses `idempotent_backfill`, so a batch that committed before the process died is skipped on replay and the final outcome rows equal an uninterrupted run (TST-RUN-07).
- D-08 (Verified Fact) Run totals reconcile with the `intake_outcome` rows whose run id lies in `[run_id + ".b", run_id + ".c")`; a mismatch fails the run (E-RUN-TOTALS-MISMATCH).
- D-09 (Verified Fact) Jobs cannot reach Zone H: `jobs`, `service`, `sources`, `flag`, `detector` import nothing from `hub.gate`; only `schedule.py` does (ZH-09). TST-RUN-12 checks the import graph and a denylist of Zone H method names, and forces a service-identity call at run time (E-GATE-NOT-AUTHORISED, run RUN_FAILED, attempt audited as denied).
- D-10 (Verified Fact) Metrics are computed deterministically from stored rows with exact `Decimal` arithmetic. Money = `Decimal(repr(float))`, quantised to 2 places ROUND_HALF_EVEN at presentation only (assumed currency minor unit 2, RTD-61). Median = mean of the two middle values; p90 = nearest rank ceil(0.9 n) (spec choices, A-12-F07-1). n = 0 gives null with a reason, never 0.
- D-11 (Verified Fact) Definition tags are mandatory where required (E-MET-TAG-REQUIRED); `combine` and `compare` raise E-MET-TAG-MIX for different tags or policy versions; `side_by_side` never derives a cross-column value; `trend` flags FAIL-02-conflict and produces no cross-definition headline.
- D-12 (Verified Fact) Month-end total: `cutoff_ts` and `denominator_ref` are required (E-MET-CUTOFF-REQUIRED, OD-S12-08); one query on one table (no join, the BB-08 fan-out); `operating_costs` is refused as 'cases created' (OD-07). Shipped baseline: 622826.44, n = 125 (legacy 742,956.61 not produced).
- D-13 (Verified Fact) Stored metric values keep parameters and inputs (`params`, `inputs`, `inputs_hash`); `reproduce` recomputes with a `recorded_until` bound or the stored row ids, so unrelated later data do not change the result; a code change that alters it is E-MET-NOT-REPRODUCIBLE.
- D-14 (Verified Fact) Backlog by site implements the state-based D-OPS definition only (DEV-69); a date-only `as_of` is the end of that day (the K-09-OPS baseline of 89 counts the cases created on 2025-12-19). Unresolved-exception rate = open exception-queue items / all items that sat in a queue (A-12-F07-2, a spec choice).
- D-15 (Verified Fact) Observability: `hub/obs/log.py` writes JSON lines with a fixed field whitelist (ids pattern-checked, free text cannot reach a log line), duration measured with the injected clock; `hub/obs/collect.py` derives normative metrics from stored rows and stores them in `obs_metric`; zero-tripwires (model calls, egress attempts, service actor accepted at Zone H) are exported at the end of every run. Reports (health, latency, kpi-coverage, queues, selfcheck) are read-only; latency prints p50/p95 and no pass/fail (PNFR-06 target Unknown, OPD-14).
- D-16 (Verified Fact) Exit codes: 29 for E-RUN-*, 30 for E-MET-* (INC-07 choices, RTD-58). CLI results go to stdout, JSON log lines to stderr.
- D-17 (Verified Fact) TST-CO-12 is frozen: INC-07 modules skip when `HUB_EGRESS_INNER` is set; `test_inc07_egress_guard.py` (E07EGRESS) runs them under the guard (0 attempts, model_calls_total 0) in its own device-call group.
- D-18 (Verified Fact) Clock abstraction only: no `time`, `random`, `secrets` import in `hub/runs`, `hub/metrics`, `hub/obs` (S14); `hub/obs` also imports no `datetime`.

- RR-D7-2 Metric verdicts stay `not_available_no_adopted_policy` until a human adopts a definition, a clock duration and a cut-off.

# INC-08 design notes (loopback HTTP surface, reviewer queue, disposition gate)
Branch `stage-15-inc08-http-reviewer`. Labels: Verified Fact / Inference / Assumption / Unknown. Test data synthetic, unvalidated. No AI/model call, no network egress beyond loopback, `zone_h.holders` EMPTY in the shipped configuration (the tests use two synthetic holders, labelled as such). Disposition mode is `none` by default.

## Decisions
- D-01 (Verified Fact) One framework-free `WebApp.handle(Request) -> Response` serves both the in-process tests and a stdlib `ThreadingHTTPServer` (`hub/web/server.py`). The server binds the configured address only if it is loopback (`bind_address`), drops non-loopback peers (`verify_request`), answers one request per connection (`Connection: close`) and skips `getfqdn`. Any non-loopback bind is refused with the exposure error even when an approval is configured: INC-08 makes no TLS-termination or external-exposure claim (Stage 24 decides, A-INC08-1..5).
- D-02 (Verified Fact) M006 (`hub/web/migrations/M006_web_gate_review.sql`) is applied only by `hub.web.schema` after a backup labelled `pre-web-M006-`, recorded in its own table `web_schema_migrations` (not `schema_migrations`: the M002..M005 precedent, a file in `hub/store/forward/` would break `migrate.known_versions()`). It adds `service_token`, `service_token_revocation`, `rule_trace`, `flag_action`; all four are insert-only (triggers, `E-SEC-RETAINED`). It needs M001..M005. Forward-only; rollback is backup restore (`rollback-rehearsal-inc08.md`).
- D-03 (Verified Fact) Request precedence in `WebApp._dispatch`: body size (413) -> route match (an unlisted method/path is 403 E-AUTH-FORBIDDEN, deny by default, audited) -> body parse (400) -> authentication (401; UI pages redirect 303 to /ui/login) -> CSRF (403 E-SEC-CSRF, audited) -> role authorisation (`WebAuthorizer`) -> handler. The 48 operations of the frozen route registry and the 10 page routes of `hub/web/ui_routes.json` are separate files; the OpenAPI-pinned registry (TST-SEC-01) stays frozen.
- D-04 (Verified Fact) Credentials: `Authorization: Bearer <token>` or the `hub_session` cookie. `CompositeAuthenticator` treats `svc_...` tokens as service tokens (role `integration`, never a fresh re-authentication) and everything else as a human session. Only the SHA-256 of a service token is stored; it is shown once at issue (`python -m hub.web token issue`), revoked by token or 8-hex digest prefix, and may expire. A human principal cannot hold one (A-INC08-1).
- D-05 (Verified Fact) CSRF: JSON writes need `X-Hub-Request: 1` (no CORS headers are ever sent, so a cross-site form or fetch cannot set it); form posts need `csrf_token = sha256("csrf:" + session digest)`, derived and not stored. The login POST has no pre-session token (A-INC08-5).
- D-06 (Verified Fact) Every response carries nosniff, CSP `default-src 'self'`, no-store, Referrer-Policy, X-Frame-Options and `X-Correlation-Id`. The session cookie is HttpOnly, SameSite=Strict, Path=/ and has no `Secure` flag over plain loopback HTTP (A-INC08-3). The login response also returns the session token and CSRF token in the body for non-browser clients (A-INC08-4).
- D-07 (Verified Fact) Zone H on HTTP: `POST /api/v2/zone-h/actions` and the disposition form go through `ZoneHActions.execute`, the single choke point: `require_holder` is called once, before the payload is read; the audit sequence of that check is handed to the delegate through a one-shot `_Preapproved` object. `reauth_token = sha256("reauth:" + session digest + ":" + reauth_at)`, obtained from OP-SEC-05 (A-INC08-2). An unknown action name is judged by the choke point before identity (422, no effect); an anonymous caller with a well-formed action is 401 (DEV-85).
- D-08 (Verified Fact) Disposition gate: `disposition.mode` is `none` by default (E-GATE-MODE-NONE 423); `event` mode with empty `values` is E-GATE-VALUES-UNSET; `external_ref` stores DISPOSITION_REFERENCED with `verified = false` and no state change. A stale `pack_hash` is E-GATE-PACK-STALE (409, retryable) and is audited as ZONE_H_REFUSED. The evidence pack read (OP-GATE-01) is role-gated to dispositioners. A disposition is never produced by any automated caller (TST-GATE-11 import graph).
- D-09 (Verified Fact) Reviewer support: the exception queue lists intake queue items and stored rule traces with one flag id each; the explanation page shows function, rule set, inputs and output, and offers override / dismiss / refuse with a mandatory reason; the original rule output is never changed (insert-only `rule_trace`, `flag_action`, OVERRIDE_RECORDED event with `affects_state` false). Untrusted text is escaped and labelled "untrusted source text".
- D-10 (Verified Fact) Metric GETs are computed with `store=False` by a `MetricsService` whose clock is pinned to the data horizon (the latest of `decision_events.recorded_at`, `raw_intake.receipt_time`, `intake_outcome.decided_at`), so two identical GETs return identical JSON (AC-MET-21) and `computed_at` / `window_end` are data instants, not wall-clock times (DEV-79).
- D-11 (Verified Fact) Search (OP-REV-03) is the deterministic fallback engine only, disabled by default (`search.enabled`), over an injected document provider; FTS5 and the corpus loader are INC-09 (DEV-81, RTD-68). The R2 criteria TST-REV-10/14/16/17 are tested against it and are not an R1 claim.
- D-12 (Verified Fact) Test split and the loopback exception: INC-08 modules skip inside TST-CO-12's inner run (`HUB_EGRESS_INNER`, frozen group C keeps its 5 tests) and run in their own egress-guarded group `E08EGRESS` (`test_inc08_egress_guard.py`, recursion guard `HUB_EGRESS_INNER8`). The tests open real listener sockets on 127.0.0.1 (ephemeral ports) and connect to them; the egress guard already allows loopback and refuses everything else, so no relaxation was needed and the exception is confined to 127.0.0.1 (the inner run asserts zero egress attempts). The client is a raw-socket helper because the No-AI rule R2 forbids `http.client` / `urllib.request` (also in `tests/hub`). The 11 INC-08 tests that the plan files under TST-DEC / TST-INT / TST-MET / TST-RUN / TST-SEC are named `test_I8_<FAMILY>_<NN>_...` so the frozen selectors of the earlier groups (`-k TST_SEC`, ...) keep selecting the same tests; the INC-08 group selects them with `-k I8_`.
- D-13 (Verified Fact) The web app opens the store through `hub.store.db.open_hub` (path guard + core migration check), not `sqlite3.connect`, because TST-CO-04 d allows `sqlite3.connect` only in the store, the runtime check and the read-only adapter (found by the first full group-B run; DEV-86).
- D-14 (Verified Fact) HTTP observability (`hub/web/obs_http.py`, closes the HTTP part of RTD-60): `http_requests_total{op_id,status}`, `http_request_duration_ms{op_id}`, `auth_failures_total{reason}` and the derived `override_total`, `defaulted_outputs_total`; label sets are closed (registry op ids, numeric status, fixed reasons, `UNROUTED`); durations use the injected clock. Log lines are `hub.obs.log` JSON lines (`http_request`, `fts_engine_selected`, `startup_selfcheck`).
- D-15 (Verified Fact) NFR measurements are pure helpers (`hub/web/nfr.py`: availability, timeliness, latency) over supplied records; the tests print the figures with method and the label "against an unvalidated working target". Nothing asserts a real-world target (A-09-04, OPD-14): latency has no threshold (PNFR-06).
- D-16 (Verified Fact) Determinism: no `time` or `random` in the core modules; ids and tokens use `os.urandom`; durations come from the clock abstraction (`FixedClock` advances 1 microsecond per call in tests). TST-NFR-17 compares 13 read responses across `PYTHONHASHSEED` 0/1/random, TZ UTC / Asia/Kolkata / America/Los_Angeles and LC_ALL C / de_DE.UTF-8 / tr_TR.UTF-8 (child processes, fixed correlation id).
- D-17 (Verified Fact) New codes (Stage 12 addendum, RTD-66): exit code 31 for the INC-08 family (`E-REQ-INVALID` use on the wire, `E-REQ-TOO-LARGE` 413, `E-REQ-NOT-IMPLEMENTED` 501, `E-REV-*` including `E-REV-DRAFTS-DISABLED` and `E-REV-SEARCH-DISABLED` 501, `E-GATE-MODE-NONE` / `E-GATE-VALUES-UNSET` 423, `E-GATE-PACK-STALE` 409, `E-GATE-REASON-REQUIRED`, `E-GATE-EXTREF-INVALID`, `E-GATE-PAYLOAD-INVALID` 422), `E-SEC-CSRF` 403 with exit code 19; config keys `disposition.*`, `search.*`.
- D-18 (Verified Fact) Operator CLI `python -m hub.web`: `status`, `migrate`, `serve [--port N]` (self-check first: exposure guard, schema, CONFIG_LOADED audit with command `web-serve`), `token issue|revoke`, `record-trace`. Results on stdout, JSON log lines on stderr.

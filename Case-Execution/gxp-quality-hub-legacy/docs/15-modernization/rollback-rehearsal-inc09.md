Verified Fact, sandbox only (OD-03/03a). Two levels, both executed by tests (`docs/14-transformation/rollback-strategy.md` row INC-09: "`search.fts=off`; drop derived index"):
- **L1 flag / derived index** - `search.fts = off` returns the fallback engine (S03); `python -m hub.search drop-index` (or `hub.search.corpus.drop`) removes the FTS5 tables and the derived rows, writes a DROPPED provenance row and one audit record; search answers E-REV-INDEX-ABSENT; a rebuild from the same inputs gives byte-identical search responses (S04, S07). No record is lost: the corpus is derived from the read-only legacy files.
- **L2 schema** - `python -m hub.search migrate` takes a `pre-search-M007-` backup and applies M007 to an INC-08 store; after corpus and draft writes, `hub.ops.backup.restore` of that backup gives the M006 store back (M007 absent, `search_doc` absent, audit chain verifies `ok`); a second migrate applies M007 again (S13). Drafts and findings written after the backup are lost by an L2 restore (insert-only records; the restore sets the replaced file aside under `pre-restore/`).
Legacy code and `data/` are not involved in either level (backup checksum rc 0 before and after every run). Synthetic, unvalidated.

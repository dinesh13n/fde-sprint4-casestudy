# INC-07 rollback rehearsal (M005)
Verified Fact, sandbox only (OD-03/03a): `TST-HUB-INC07-S18` passes. Procedure: (1) `python -m hub.runs migrate --data-dir <store> --backup-root <dir>` takes a backup labelled `pre-runs-M005-` and applies M005; (2) runs and a metric snapshot are executed; (3) `hub.ops.backup.restore` restores the backup: checksum matches the manifest, the newer store is set aside (not deleted), the run / metric / observability tables are gone, the decision record is unchanged and the audit chain verifies; (4) roll forward re-applies M005 and a run works again (one run record, chain verifies). Rollback is by backup restore only; there is no down migration. Run and metric rows written after the backup are lost from the live store but remain in the set-aside copy. The rehearsal was run on synthetic data in a sandbox copy; production rollback needs the same procedure under human approval.

# INC-09 design notes (R2: FTS5 search, derived corpus, R2 reports, templates)
Branch `stage-15-inc09-search-corpus` (from `main` with OD-21 and OD-22). Labels: Verified Fact / Inference / Assumption / Unknown. Test data synthetic, unvalidated. No AI / model call, no embeddings, no network egress, `zone_h.holders` EMPTY in the shipped configuration (tests use two synthetic holders, labelled as such). Entry: OD-22 (Dinesh approved the Initial PRD as the baseline, refine at Stage 17), so INC-09 may start; every other choice is the Stage 14 default under OD-12.

## Summary
INC-09 delivers the R2 scope of the Stage 14 plan (TB-21, C10 plus the R2 parts of C3/C4/C6/C7/C9/C2): keyword / field search on SQLite FTS5 behind `search.fts` (default `off`) with a runtime-detected fallback, a derived and rebuildable corpus index (dropping it is the rollback), deterministic template drafts (deferred by default), and the five operations that answered 501 in INC-08 (OP-POL-07, OP-INT-04, OP-ID-04, OP-ID-05, OP-MET-06). All 20 planned INC-09 tests pass; every earlier group and the characterization harness stay green.

## Findings / decisions
- D-01 (Verified Fact) Packages: `hub/search/` (settings, fts probe and selection, text rules, corpus loader, R2 search service, M007 applier, CLI) and `hub/r2/` (divergence, intake reports, joined view, consistency, source quality, protection, drafts + `templates.json`, facts, errors, R2 API handlers, `R2WebApp`, CLI). Only added files; no earlier module was edited. `hub.review.search.SearchService` (INC-08, frozen) is extended by the subclass `R2SearchService`; `hub.web.app.WebApp` by the subclass `R2WebApp`, whose `api` attribute is `hub.r2.api` (R2 handlers; every other operation delegates through a module `__getattr__` to the frozen `hub.web.api`). The route registry and its roles are unchanged (TST-SEC-01).
- D-02 (Verified Fact) M007 (`hub/search/migrations/M007_search_r2.sql`), own table `search_schema_migrations`, applied by `hub.search.schema` after a `pre-search-M007-` backup, requires M001..M006. Tables: `search_doc` (derived corpus rows, NOT insert-only by design), `search_corpus_load` (provenance, insert-only), `consistency_finding` (insert-only, UNIQUE rule_ref + object_refs + policy_version), `review_draft` (insert-only). The plan's "M006 (opt.) FTS5 virtual table" became M007 because INC-08 used M006; the FTS5 virtual tables are not part of any migration (D-04).
- D-03 (Verified Fact) Flag `search.fts` = `auto` | `off`, default `off` (feature-flag-plan). `search.enabled` (INC-08 key, default false) still gates OP-REV-03. The engine is chosen per request by `hub.search.fts.select`: `fts5` only when the flag is `auto` AND the runtime offers FTS5 + trigram (detected at run time with TEMP virtual tables on the store connection - no new `sqlite3.connect`, TST-CO-04 d) AND the derived FTS tables exist; otherwise `fallback` with the reason `flag_off`, `fts5_unavailable` or `fts_index_not_built`. The response carries `engine` and `engine_reason`; `R2WebApp.start()` logs `fts_engine_selected` with `search-engine:<engine>:<reason>`. Device runtime: Python 3.10.12, SQLite 3.37.2 with FTS5 and trigram (OD-S12-12 floor 3.10 / 3.37); the target runtime is Unknown (RTD-79).
- D-04 (Verified Fact) Corpus loader (`hub/search/corpus.py`): reads ONLY a sandbox copy of the legacy tree (sandbox guard; the working tree is refused with E-CO-NOT-SANDBOX): `data/documents/source_documents.jsonl` (sha256 pinned to the Stage 0A manifest value; a mismatch fails closed with E-FX-HASH) and the 420 `data/archive_documents/*.eml|*.html` (each file hashed; `manifest.json` ignored). Archive items: visible text (quoted-printable decoded, `<title>` excluded), `doc_id` `ARC-<stem>`, `effective_at` from the "Source date" in the text, locale and reference null, access level `restricted` with `access_level_given = 0` (MA-1). One transaction rebuilds `search_doc` and, when available, the external-content FTS5 tables `search_fts` (unicode61) and `search_tri` (trigram) over the folded text; one audit record and one provenance row per load or drop. `drop` (CLI `python -m hub.search drop-index`) is the L1 rollback: FTS tables dropped, rows deleted, provenance row DROPPED; search then answers E-REV-INDEX-ABSENT (409).
- D-05 (Verified Fact) Query handling: the INC-08 grammar (terms, quoted phrases, `ref:` `doc:` `locale:` `version:` `from:` `to:`, 200 characters / 12 terms) with the INC-09 token rule `[^\W_]+` on NFKD-folded, case-folded text (the unicode61 boundary). Terms containing Han / Kana / Hangul are substring terms: `search_tri MATCH` for >= 3 characters, `instr()` on the folded text for shorter ones. The MATCH argument is ONE bound parameter in which every term / phrase is double-quoted; `OR`, `NOT`, `NEAR`, `*`, `:` have no effect; any SQLite error is mapped to E-REV-QUERY-INVALID without detail (AC-REV-11). Field filters and the access filter are in the same SQL statement, before ranking and counting.
- D-06 (Verified Fact) Ranking: `bm25(search_fts)` on the FTS5 engine; the fallback computes the same bm25 formula (k1 1.2, b 0.75, idf floor 1e-6, whole-corpus statistics as FTS5 computes them) in Python. Both are rounded to 1e-9 and then ordered by effective_at descending and doc_id, so both engines return identical pages (S01 over 18 queries x 2 roles x 3 paging modes; S12 checks the formula against SQLite's bm25()). Snippets are the INC-08 escaped excerpt on both engines (not FTS5 `snippet()`), so responses do not depend on the engine (DEV-93).
- D-07 (Verified Fact) Data protection (`hub/r2/protection.py`, BEH-SEC-10): field classes C1..C3 per metadata-model M2/M3 (C0 has no data in the estate), the M4 role matrix, masking of `account_id` for finance_read, missing / unknown access level = restricted, unmapped field = restricted. C3 rule: when the PERMITTED result of a search or a joined view contains restricted rows, a non-empty `reason` query parameter is required (E-SEC-REASON-REQUIRED, 422, nothing returned) and the read is audited as `C3_READ` with the reason in the audit `reason` column. A caller who may not read restricted rows never sees, counts or is asked a reason for them.
- D-08 (Verified Fact) OP-POL-07 divergence (`hub/r2/divergence.py`): every loaded set publishing `amount_over_limit` (PRIORITY / AMOUNT_LIMIT / SHIFT_FLAG normalisers, A-12-F03-1) over the injected case inputs (the 125 shipped cases from the read-only snapshot); a case is divergent when its non-null outputs differ. Shipped result: 3 of 125 divergent (python vs js); the batch set gives null for all 125 (it needs region + policy_code, the cases carry no policy_code). The count is recorded in `RULE_DIVERGENCE_REPORTED`; nothing is resolved or activated and no set is named correct.
- D-09 (Verified Fact) OP-INT-04 (`hub/r2/intake_reports.py`): delay = receipt_time - source_ts per item (exact decimal hours), flags FUTURE_SOURCE_TS / MISSING_SOURCE_TS / REVISED, share within `intake_reports.delay_threshold_hours` (default 4, Assumption) over usable non-future delays; `?view=freshness&as_of=` on the same path gives the age of the newest accepted item (VALIDATED / VALIDATED_WITH_FLAGS) against `intake_reports.freshness_hours` (default 24, Assumption). Unknown source / no item -> E-INT-ITEM-NOT-FOUND.
- D-10 (Verified Fact) OP-ID-04 joined view (`hub/r2/joined.py`): BFS over active links, depth cap 4, size cap 500 (`crosswalk_view.*`), order (type, id), same set from every member within the cap, `truncated` + `total` (full permitted count) when capped, `depth_capped` when the depth cap cut a branch. Denied documents appear as `{type: document, access: denied}` without id and are not counted; links touching them are hidden. Role / id-pattern rules are the OP-ID-01 rules (the INC-05 `lookup` is called first).
- D-11 (Verified Fact) OP-ID-05 consistency (`hub/r2/consistency.py`): rules are ADOPTED `CONSISTENCY` policy objects (none ships adopted; adoption is ZH-05 with a holder). The check is an operator command (`python -m hub.r2 consistency-check`) or service call - the registry has only the GET; it writes finding rows with INSERT OR IGNORE on the unique key (idempotent), changes nothing else, never auto-corrects, and is audited once per run. `case.state` comes from the decision projection, every other field from the read-only legacy facts; vocabularies are never mapped (BEH-ID-08). The GET lists findings and adds the statement 'no consistency policy adopted' when none is adopted.
- D-12 (Verified Fact) Test split: the 20 planned tests are named `test_I9_<FAMILY>_<NN>_...` (families ID, INT, MET, NFR, POL, REV, SEC) so the frozen earlier selectors (`-k TST_ID`, `-k TST_REV`, `-k TST_SEC`, `-k TST_NFR`, `-k I8_`, ...) keep their counts; the INC-09 group is `-k I9_ -k INC09_S` (20 planned + 13 supplementary) and `-k E09EGRESS` runs both again under the egress guard (recursion guard `HUB_EGRESS_INNER9`). INC-09 modules skip inside TST-CO-12's inner run (`HUB_EGRESS_INNER`), so group C keeps its 5 tests. INC-09 opens no socket (in-process app only). No test was added to TST-CO-12.
- D-13 (Verified Fact) OP-MET-06 (`hub/r2/source_quality.py`): unmatched_reference_rate (UNMATCHED_REF or NO_BUSINESS_KEY among the current reasons / validated items) and the reconciliation-delay distribution (RUN_FINISHED of the first outcome's run minus receipt_time; n, min, p50, p95, max, nearest rank) per source, metric-value shaped, computed as of the data horizon (INC-08 D-10) and not stored; `inputs_hash` covers every input row. OP-MET-05 stays E-MET-NOT-AVAILABLE.
- D-14 (Verified Fact) OP-REV-04 drafts (`hub/r2/drafts.py`, `templates.json`): `templates.enabled` default false (E-REV-DRAFTS-DISABLED); when enabled, a human reviewer / quality_lead / compliance stores exactly the typed fields of a deterministic template (labels, types, length limits; nothing pre-filled), owned by the author, insert-only, audited with field names only. The module imports neither hub.gate nor hub.decision.service; the response offers no action.
- D-15 (Verified Fact) Determinism and guards: no `time` / `random` / `secrets` import and no wall-clock call in hub/search or hub/r2 (S08); `datetime` is used only to parse stored timestamps; the clock is injected. No HTTP client, no AI package (deny-list scan of the new paths is empty). The operator CLIs install the egress guard and use the hub.admin run wrapper (runtime floor, hub.kill, CONFIG_LOADED, anchor).
- D-16 (Verified Fact) New codes and keys (Stage 12 addendum, RTD-78): E-REV-INDEX-ABSENT 409 and E-R2-INPUT-INVALID 422 with exit code 32 (INC-09 family); E-SEC-REASON-REQUIRED 422 (registry code) with exit code 19; audit actions SEARCH_SCHEMA_APPLIED, SEARCH_CORPUS_LOADED, SEARCH_CORPUS_DROPPED, C3_READ, RULE_DIVERGENCE_REPORTED, CONSISTENCY_CHECK_RUN, DRAFT_CREATED; config keys `search.fts`, `search.max_doc_chars`, `search.require_c3_reason`, `templates.enabled`, `crosswalk_view.depth_cap|size_cap`, `intake_reports.delay_threshold_hours|freshness_hours`; query parameters `reason` (OP-REV-03, OP-ID-04), `view` / `as_of` (OP-INT-04), `window_start` / `window_end` / `source` (OP-MET-06); response fields `engine_reason`, `depth_capped`, `null_outputs`, `count`.
